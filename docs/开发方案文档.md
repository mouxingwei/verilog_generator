# Verilog 模块结构与连线管理工具开发方案文档

日期：2026-05-13

## 1. 开发目标

构建一个面向 Verilog-2005 顶层结构代码快速生成的工具链。工具从已有 Verilog 模块、亿图 SVG 算法框图、Excel 定点信号表和 YAML 映射配置等输入中提取结构信息，汇总为统一 IR，经过校验后生成多层级 Verilog `.v` 结构代码。

第一阶段目标是打通以下闭环：

```text
已有 Verilog-2005 模块库
  -> 提取模块端口/参数/位宽

亿图 SVG 算法框图
  -> 提取 block、层级、信号连接

Excel 定点信号表 + YAML 映射配置
  -> 提取信号定点格式、block 到模块映射、端口补充映射

统一 IR
  -> 校验
  -> 生成多层级 Verilog .v 代码
  -> Icarus Verilog 语法检查
  -> React Flow 只读拓扑预览
```

第一阶段生成代码范围：

1. 顶层或子系统 module 声明。
2. 内部 wire 声明。
3. 子模块例化。
4. parameter 参数传递。
5. named port connection 端口连接。
6. 必要的 assign 直连语句。

第一阶段不生成完整 RTL 行为逻辑，不做图形化编辑，不生成 SystemVerilog `.sv`。

## 3. 输入到 IR 的主流程

### 3.1 Verilog 模块库输入

输入：

```text
rtl/*.v
```

处理：

```text
Pyverilog
  -> parse Verilog-2005
  -> extract module name
  -> extract parameters
  -> extract ports
  -> extract direction and width expression
  -> normalize into IR modules
```

输出 IR 区域：

```yaml
modules:
  - name: fir_filter
    source: rtl/fir_filter.v
    parameters:
      - name: DATA_W
        default: 16
      - name: TAP_NUM
        default: 32
    ports:
      - name: clk
        direction: input
        width: 1
      - name: din
        direction: input
        width_expr: DATA_W
      - name: dout
        direction: output
        width_expr: DATA_W
```

### 3.2 亿图 SVG 框图输入

输入：

```text
examples/algo/algo.svg
```

处理：

```text
SVG parser
  -> read shapes/text labels
  -> identify block nodes
  -> identify hierarchy/group if available
  -> identify connection lines
  -> preserve stable signal names from diagram
  -> normalize into algorithm_blocks and algorithm_connections
```

输出 IR 区域：

```yaml
algorithm_blocks:
  - id: blk_fir
    name: fir0
    block_type: FIR
    hierarchy: top.u_dsp

algorithm_connections:
  - signal: sample_in
    source_block: input
    source_port: sample
    target_block: fir0
    target_port: din
```

说明：

1. 第一阶段以 SVG 为主输入，`.eddx` 只作为备选验证对象。
2. 框图中已有稳定信号名，工具不主动重命名。
3. 如果 SVG 中连接关系无法可靠解析，导入器应输出 ERROR 或 WARNING，并要求补充映射表。

### 3.3 Excel 表格输入

第一阶段 Excel 至少定义一个信号属性表。block 到 Verilog module 的映射关系使用 YAML 配置文件维护。

#### fixed_signals

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| signal | 信号名，必须与框图连线名一致 | sample_in |
| fixed_format | 定点格式 | s(11,1) |
| description | 可选说明 | ADC sample |

定点格式：

```text
s(11,1) = signed, 总位宽 11, 小数位 1
u(11,5) = unsigned, 总位宽 11, 小数位 5
```

解析后进入 IR：

```yaml
signal_attributes:
  - signal: sample_in
    fixed_format: s(11,1)
    signed: true
    width: 11
    frac_width: 1
```

### 3.4 YAML 映射配置输入

#### block_mapping.yaml

block 到 Verilog module 的映射关系使用 YAML 配置文件维护，而不是 Excel 表。

示例：

```yaml
block_mappings:
  - block_type: FIR
    module: fir_filter
    instance_prefix: u_fir
    parameter_overrides:
      DATA_W: "{signal_width:din}"
      FRAC_W: "{signal_frac_width:din}"
```

#### port_mapping.yaml

端口匹配默认使用同名规则；当框图端口名和 Verilog 模块端口名不一致时，通过端口映射配置补充。

示例：

```yaml
port_mappings:
  - block_type: FIR
    module: fir_filter
    ports:
      input: din
      output: dout
      clock: clk
      reset_n: rst_n
```

映射后进入 IR：

```yaml
instances:
  - name: u_fir0
    module: fir_filter
    hierarchy: top.u_dsp
    parameters:
      DATA_W: 11
```

## 4. 统一 IR 设计

IR 是唯一生成源。所有输入都先归一化到 IR，再进行校验和生成。

### 4.1 核心实体

| 实体 | 作用 |
| --- | --- |
| Module | 从 Verilog 模块库提取的模块定义 |
| Port | 模块端口定义 |
| Parameter | 模块参数定义 |
| AlgorithmBlock | 从亿图框图提取的算法 block |
| BlockMapping | 框图 block 到 Verilog module 的映射 |
| PortMapping | 框图端口到 Verilog module 端口的补充映射 |
| Instance | 根据 block 和 mapping 生成的模块实例 |
| Net | 由框图信号和定点表生成的内部信号 |
| Connection | 实例端口到 net 的连接 |
| SignalAttribute | 信号定点格式和位宽属性 |
| Hierarchy | 多层级路径和子系统边界 |

### 4.2 IR 生成规则

1. `Module` 只来自 Verilog 提取或人工补充。
2. `AlgorithmBlock` 只来自框图导入。
3. `SignalAttribute` 主要来自 Excel 定点信号表。
4. `BlockMapping` 和 `PortMapping` 来自 YAML 配置文件。
5. `Instance` 由 `AlgorithmBlock + BlockMapping` 生成。
6. `Net` 由框图连接信号名和定点表共同生成。
7. `Connection` 由框图连接关系、默认同名端口规则和 `PortMapping` 补充规则生成。
8. `Hierarchy` 可来自框图分组、路径字段或后续人工补充。

### 4.3 多层级表示

多层级工程使用层级路径表达：

```yaml
instances:
  - name: u_fir0
    module: fir_filter
    hierarchy: top.u_dsp

nets:
  - name: sample_in
    hierarchy: top.u_dsp
    width: 11
```

生成时按 hierarchy 分组，分别生成对应层级 module。第一阶段支持按层级生成多个 `.v` 文件，而不是只生成单个展开式 `top.v`。

示例输出：

```text
generated/
  top.v
  top_u_dsp.v
  top_u_ctrl.v
```

## 5. IR 合并流程

```text
1. import-verilog
   Verilog .v -> modules

2. import-algo-svg
   亿图 SVG -> algorithm_blocks + algorithm_connections

3. import-excel
   fixed_signals.xlsx -> signal_attributes

4. import-mapping
   block_mapping.yaml -> block_mappings
   port_mapping.yaml -> port_mappings

5. merge
   algorithm_blocks + block_mappings -> instances
   algorithm_connections + signal_attributes -> nets
   instances + modules + algorithm_connections + port_mappings -> connections

6. validate
   schema check
   reference check
   semantic check

7. generate-verilog
   IR -> generated/*.v

8. syntax-check
   generated/*.v -> Icarus Verilog

9. generate-reactflow
   IR -> graph.reactflow.json -> read-only preview
```

## 6. 参数传递方案

参数来源优先级：

1. 用户在 `block_mapping.yaml` 中显式配置的 parameter override。
2. 由定点格式推导的常用参数，例如 `DATA_W`、`FRAC_W`。
3. Verilog 模块定义中的 parameter default。

示例：

```yaml
modules:
  - name: fir_filter
    parameters:
      - name: DATA_W
        default: 16
      - name: FRAC_W
        default: 0

instances:
  - name: u_fir0
    module: fir_filter
    parameters:
      DATA_W: 11
      FRAC_W: 1
```

生成代码：

```verilog
fir_filter #(
    .DATA_W(11),
    .FRAC_W(1)
) u_fir0 (
    .clk(clk),
    .din(sample_in),
    .dout(filtered_out)
);
```

参数校验：

1. override 的参数名必须存在于目标 module。
2. 参数值可以是整数或表达式文本。
3. 由定点格式推导的参数必须与信号位宽一致。
4. 生成例化代码时只显式输出传参参数；未覆盖参数使用 Verilog 模块默认值，不在例化中重复输出。

## 7. 信号连接方案

### 7.1 net 生成

每条框图信号边生成一个 net：

```yaml
nets:
  - name: sample_in
    width: 11
    signed: true
    frac_width: 1
```

Verilog 声明：

```verilog
wire signed [10:0] sample_in;
```

如果 `width == 1`：

```verilog
wire valid;
```

### 7.2 端口连接生成

连接由框图中的 source/target block、默认同名端口匹配规则和 `port_mapping.yaml` 补充规则得到。

```yaml
connections:
  - instance: u_fir0
    port: din
    net: sample_in
  - instance: u_fir0
    port: dout
    net: filtered_out
```

Verilog 生成：

```verilog
fir_filter #(
    .DATA_W(11),
    .FRAC_W(1)
) u_fir0 (
    .clk(clk),
    .din(sample_in),
    .dout(filtered_out)
);
```

### 7.3 连接校验

1. 每个 connection 的 instance 必须存在。
2. 每个 port 必须存在于对应 module。
3. 每个 net 必须存在。
4. input 端口应连接到已有 net。
5. output 端口可驱动 net，但同一 net 不允许多个 output 驱动，除非显式标注允许。
6. net 位宽与 port 位宽不一致时，第一阶段允许自动截断或扩展，并输出 WARNING。

### 7.4 位宽不匹配处理

第一阶段位宽不匹配不直接阻塞生成，而是自动插入转换逻辑并输出 WARNING。

处理规则：

1. net 宽度大于端口宽度：默认自动截断低位，后续可通过映射配置指定 slice。
2. net 宽度小于端口宽度：根据 signed 属性进行符号扩展或零扩展。
3. 每一次自动转换都必须生成 warning 报告，包含 instance、port、net、原始位宽、目标位宽和转换方式。

示例：

```verilog
// WARNING: auto truncate sample_wide[15:0] to fir din[10:0]
wire [10:0] sample_wide_to_u_fir0_din = sample_wide[10:0];

// WARNING: auto sign extend sample_narrow[7:0] to fir din[10:0]
wire signed [10:0] sample_narrow_to_u_fir0_din = {{3{sample_narrow[7]}}, sample_narrow};
```

## 8. Verilog 生成方案

### 8.1 生成文件结构

第一阶段按层级生成多个 `.v` 文件。

```text
generated/
  top.v
  top_u_dsp.v
```

`top.v` 示例：

```verilog
// Generated by verilog_generator.
// Source IR: examples/basic_design.yaml

module top (
    input clk,
    input rst_n
);

wire signed [10:0] sample_in;
wire signed [10:0] filtered_out;

top_u_dsp u_dsp (
    .clk(clk),
    .rst_n(rst_n),
    .sample_in(sample_in),
    .filtered_out(filtered_out)
);

endmodule
```

`top_u_dsp.v` 示例：

```verilog
module top_u_dsp (
    input clk,
    input rst_n,
    input signed [10:0] sample_in,
    output signed [10:0] filtered_out
);

fir_filter #(
    .DATA_W(11),
    .FRAC_W(1)
) u_fir0 (
    .clk(clk),
    .rst_n(rst_n),
    .din(sample_in),
    .dout(filtered_out)
);

endmodule
```

### 8.2 生成排序

为了保证 Git diff 稳定：

1. 输出文件按层级路径排序。
2. module 端口按 IR 中顺序输出。
3. net 按 hierarchy、name 排序。
4. instance 按 hierarchy、name 排序。
5. 只输出传参参数，且按模块定义顺序输出。
6. port connection 按模块端口定义顺序输出。

### 8.3 生成前置条件

生成 `.v` 前必须通过：

1. Schema 校验。
2. 引用校验。
3. 定点格式校验。
4. 位宽和方向校验。
5. 参数覆盖校验。
6. 自动截断/扩展转换计划生成。

生成 `.v` 后必须对全部生成文件执行：

```bash
iverilog -g2005 -t null -o build/syntax_check.out generated/*.v
```

Icarus Verilog 编译错误作为 ERROR；lint 类 warning 第一阶段只记录，不阻断流程。

## 10. CLI 命令设计

```bash
vg import-verilog examples/rtl/*.v -o build/modules.yaml
vg import-algo-svg examples/algo/algo.svg --signals examples/algo/fixed_signals.xlsx -o build/algo.yaml
vg import-mapping examples/algo/block_mapping.yaml --ports examples/algo/port_mapping.yaml -o build/mapping.yaml
vg merge build/modules.yaml build/algo.yaml build/mapping.yaml -o build/design.yaml
vg validate build/design.yaml
vg generate-verilog build/design.yaml -o generated/
vg syntax-check generated/*.v
vg generate-reactflow build/design.yaml -o web/public/graph.reactflow.json
vg export-excel build/design.yaml -o build/design.xlsx
```

也可以提供一键命令：

```bash

```

## 11. 校验器设计

### 11.1 Schema 校验

校验字段类型、必填字段、枚举值和基本格式。

### 11.2 引用校验

1. instance 引用的 module 必须存在。
2. connection 引用的 instance 必须存在。
3. connection 引用的 port 必须属于该 instance 对应的 module。
4. connection 引用的 net 必须存在。
5. block mapping 引用的 module 必须存在。
6. 框图 signal 必须能匹配到定点信号表。
7. port mapping 中的目标端口必须存在于目标 module。

### 11.3 语义校验

1. `s(width,frac_width)` / `u(width,frac_width)` 格式必须合法。
2. `width > 0`。
3. `0 <= frac_width <= width`。
4. port 与 net 位宽一致，或存在自动截断/扩展转换计划。
5. output/inout 驱动同一 net 时需要检查多驱动。
6. required input 不允许悬空。
7. bus slice 不能越界。
8. 参数覆盖名称必须存在。
9. 自动截断/扩展必须生成 warning 记录。

校验输出分为：

```text
ERROR   阻止生成
WARNING 允许生成但提示风险
INFO    信息提示
```

## 14. 待用户确认点

进入实现前仍需确认：

1. `block_mapping.yaml` 和 `port_mapping.yaml` 的具体字段命名是否采用本文档示例。
2. 多文件输出时，文件命名规则是否采用层级路径转下划线，例如 `top.u_dsp` -> `top_u_dsp.v`。
3. 自动截断默认取低位是否符合预期，还是需要在映射配置中指定 slice。
