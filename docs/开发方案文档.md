# Verilog 模块结构与连线管理工具开发方案文档

日期：2026-05-13

## 1. 开发目标

构建一个面向 Verilog-2005 顶层结构代码快速生成的工具链。工具从已有 Verilog 模块、亿图 SVG 算法框图、Excel 定点信号表和映射表等输入中提取结构信息，汇总为统一 IR，经过校验后生成 Verilog `.v` 顶层代码。

第一阶段目标是打通以下闭环：

```text
已有 Verilog-2005 模块库
  -> 提取模块端口/参数/位宽

亿图 SVG 算法框图
  -> 提取 block、层级、信号连接

Excel 定点信号表/映射表
  -> 提取信号定点格式和 block 到模块映射

统一 IR
  -> 校验
  -> 生成 Verilog .v 顶层代码
  -> Icarus Verilog 语法检查
  -> React Flow 只读拓扑预览
```

第一阶段生成代码范围：

1. 顶层或子系统 module 声明。
2. 内部 wire 声明。
3. 子模块例化。
4. parameter 参数传递。
5. named port connection 端口连接。
6. 必要的 assign 直连语句。

第一阶段不生成完整 RTL 行为逻辑，不做图形化编辑，不生成 SystemVerilog `.sv`。

## 3. 输入到 IR 的主流程

### 3.1 Verilog 模块库输入

输入：

```text
rtl/*.v
```

处理：

```text
Pyverilog
  -> parse Verilog-2005
  -> extract module name
  -> extract parameters
  -> extract ports
  -> extract direction and width expression
  -> normalize into IR modules
```

输出 IR 区域：

```yaml
modules:
  - name: fir_filter
    source: rtl/fir_filter.v
    parameters:
      - name: DATA_W
        default: 16
      - name: TAP_NUM
        default: 32
    ports:
      - name: clk
        direction: input
        width: 1
      - name: din
        direction: input
        width_expr: DATA_W
      - name: dout
        direction: output
        width_expr: DATA_W
```

### 3.2 亿图 SVG 框图输入

输入：

```text
examples/algo/algo.svg
```

处理：

```text
SVG parser
  -> read shapes/text labels
  -> identify block nodes
  -> identify hierarchy/group if available
  -> identify connection lines
  -> preserve stable signal names from diagram
  -> normalize into algorithm_blocks and algorithm_connections
```

输出 IR 区域：

```yaml
algorithm_blocks:
  - id: blk_fir
    name: fir0
    block_type: FIR
    hierarchy: top.u_dsp

algorithm_connections:
  - signal: sample_in
    source_block: input
    source_port: sample
    target_block: fir0
    target_port: din
```

说明：

1. 第一阶段以 SVG 为主输入，`.eddx` 只作为备选验证对象。
2. 框图中已有稳定信号名，工具不主动重命名。
3. 如果 SVG 中连接关系无法可靠解析，导入器应输出 ERROR 或 WARNING，并要求补充映射表。

### 3.3 Excel 表格输入

第一阶段至少定义两个表：

#### fixed_signals

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| signal | 信号名，必须与框图连线名一致 | sample_in |
| fixed_format | 定点格式 | s(11,1) |
| description | 可选说明 | ADC sample |

定点格式：

```text
s(11,1) = signed, 总位宽 11, 小数位 1
u(11,5) = unsigned, 总位宽 11, 小数位 5
```

解析后进入 IR：

```yaml
signal_attributes:
  - signal: sample_in
    fixed_format: s(11,1)
    signed: true
    width: 11
    frac_width: 1
```

#### block_mapping

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| block_type | 框图中的 block 类型或名称 | FIR |
| module | 映射到的 Verilog 模块名 | fir_filter |
| instance_prefix | 实例名前缀 | u_fir |
| parameter_overrides | 可选参数覆盖表达式 | DATA_W=11 |

映射后进入 IR：

```yaml
instances:
  - name: u_fir0
    module: fir_filter
    hierarchy: top.u_dsp
    parameters:
      DATA_W: 11
```

## 4. 统一 IR 设计

IR 是唯一生成源。所有输入都先归一化到 IR，再进行校验和生成。

### 4.1 核心实体

| 实体 | 作用 |
| --- | --- |
| Module | 从 Verilog 模块库提取的模块定义 |
| Port | 模块端口定义 |
| Parameter | 模块参数定义 |
| AlgorithmBlock | 从亿图框图提取的算法 block |
| BlockMapping | 框图 block 到 Verilog module 的映射 |
| Instance | 根据 block 和 mapping 生成的模块实例 |
| Net | 由框图信号和定点表生成的内部信号 |
| Connection | 实例端口到 net 的连接 |
| SignalAttribute | 信号定点格式和位宽属性 |
| Hierarchy | 多层级路径和子系统边界 |

### 4.2 IR 生成规则

1. `Module` 只来自 Verilog 提取或人工补充。
2. `AlgorithmBlock` 只来自框图导入。
3. `SignalAttribute` 主要来自 Excel 定点信号表。
4. `Instance` 由 `AlgorithmBlock + BlockMapping` 生成。
5. `Net` 由框图连接信号名和定点表共同生成。
6. `Connection` 由框图连接关系和模块端口匹配规则生成。
7. `Hierarchy` 可来自框图分组、路径字段或后续人工补充。

### 4.3 多层级表示

多层级工程使用层级路径表达：

```yaml
instances:
  - name: u_fir0
    module: fir_filter
    hierarchy: top.u_dsp

nets:
  - name: sample_in
    hierarchy: top.u_dsp
    width: 11
```

生成时按 hierarchy 分组，分别生成对应层级 module 或在顶层中展开。第一阶段优先支持“单个输出 top `.v` 内按层级命名展开”，后续再扩展为多文件分层生成。

## 5. IR 合并流程

```text
1. import-verilog
   Verilog .v -> modules

2. import-algo-svg
   亿图 SVG -> algorithm_blocks + algorithm_connections

3. import-excel
   fixed_signals.xlsx -> signal_attributes
   block_mapping.xlsx -> block_mappings

4. merge
   algorithm_blocks + block_mappings -> instances
   algorithm_connections + signal_attributes -> nets
   instances + modules + algorithm_connections -> connections

5. validate
   schema check
   reference check
   semantic check

6. generate-verilog
   IR -> generated/top.v

7. syntax-check
   generated/top.v -> Icarus Verilog

8. generate-reactflow
   IR -> graph.reactflow.json -> read-only preview
```

## 6. 参数传递方案

参数来源优先级：

1. 用户在 `block_mapping.xlsx` 中显式配置的 parameter override。
2. 由定点格式推导的常用参数，例如 `DATA_W`、`FRAC_W`。
3. Verilog 模块定义中的 parameter default。

示例：

```yaml
modules:
  - name: fir_filter
    parameters:
      - name: DATA_W
        default: 16
      - name: FRAC_W
        default: 0

instances:
  - name: u_fir0
    module: fir_filter
    parameters:
      DATA_W: 11
      FRAC_W: 1
```

生成代码：

```verilog
fir_filter #(
    .DATA_W(11),
    .FRAC_W(1)
) u_fir0 (
    .clk(clk),
    .din(sample_in),
    .dout(filtered_out)
);
```

参数校验：

1. override 的参数名必须存在于目标 module。
2. 参数值可以是整数或表达式文本。
3. 由定点格式推导的参数必须与信号位宽一致。
4. 未覆盖参数使用 Verilog 模块默认值，不重复生成也可配置为显式生成。

## 7. 信号连接方案

### 7.1 net 生成

每条框图信号边生成一个 net：

```yaml
nets:
  - name: sample_in
    width: 11
    signed: true
    frac_width: 1
```

Verilog 声明：

```verilog
wire signed [10:0] sample_in;
```

如果 `width == 1`：

```verilog
wire valid;
```

### 7.2 端口连接生成

连接由框图中的 source/target block 和 Verilog 模块端口映射得到。

```yaml
connections:
  - instance: u_fir0
    port: din
    net: sample_in
  - instance: u_fir0
    port: dout
    net: filtered_out
```

Verilog 生成：

```verilog
fir_filter #(
    .DATA_W(11),
    .FRAC_W(1)
) u_fir0 (
    .clk(clk),
    .din(sample_in),
    .dout(filtered_out)
);
```

### 7.3 连接校验

1. 每个 connection 的 instance 必须存在。
2. 每个 port 必须存在于对应 module。
3. 每个 net 必须存在。
4. input 端口应连接到已有 net。
5. output 端口可驱动 net，但同一 net 不允许多个 output 驱动，除非显式标注允许。
6. net 位宽与 port 位宽必须一致，或者显式声明 slice/extend/truncate。

## 8. Verilog 生成方案

### 8.1 生成文件结构

```verilog
// Generated by verilog_generator.
// Source IR: examples/basic_design.yaml

module top (
    input clk,
    input rst_n
);

wire signed [10:0] sample_in;
wire signed [10:0] filtered_out;

fir_filter #(
    .DATA_W(11),
    .FRAC_W(1)
) u_fir0 (
    .clk(clk),
    .rst_n(rst_n),
    .din(sample_in),
    .dout(filtered_out)
);

endmodule
```

### 8.2 生成排序

为了保证 Git diff 稳定：

1. module 端口按 IR 中顺序输出。
2. net 按 hierarchy、name 排序。
3. instance 按 hierarchy、name 排序。
4. parameter 按模块定义顺序输出。
5. port connection 按模块端口定义顺序输出。

### 8.3 生成前置条件

生成 `.v` 前必须通过：

1. Schema 校验。
2. 引用校验。
3. 定点格式校验。
4. 位宽和方向校验。
5. 参数覆盖校验。

生成 `.v` 后必须通过：

```bash
iverilog -g2005 -t null -o build/syntax_check.out generated/top.v
```

Icarus Verilog 编译错误作为 ERROR；lint 类 warning 第一阶段只记录，不阻断流程。

## 9. React Flow 只读预览方案

第一阶段预览不承担编辑职责，但使用后续编辑器同款数据模型。

```text
IR -> graph.reactflow.json -> React Flow readonly page
```

节点：

```json
{
  "id": "top.u_dsp.u_fir0",
  "type": "moduleInstance",
  "position": { "x": 100, "y": 120 },
  "data": {
    "label": "u_fir0",
    "module": "fir_filter",
    "hierarchy": "top.u_dsp"
  }
}
```

边：

```json
{
  "id": "sample_in",
  "source": "input",
  "sourceHandle": "sample",
  "target": "top.u_dsp.u_fir0",
  "targetHandle": "din",
  "data": {
    "signal": "sample_in",
    "fixed_format": "s(11,1)"
  }
}
```

第一阶段禁用：

1. 拖拽保存。
2. 新增连线。
3. 删除连线。
4. 图上直接修改属性。

## 10. CLI 命令设计

```bash
vg import-verilog examples/rtl/*.v -o build/modules.yaml
vg import-algo-svg examples/algo/algo.svg --signals examples/algo/fixed_signals.xlsx --mapping examples/algo/block_mapping.xlsx -o build/algo.yaml
vg merge build/modules.yaml build/algo.yaml -o build/design.yaml
vg validate build/design.yaml
vg generate-verilog build/design.yaml -o generated/top.v
vg syntax-check generated/top.v
vg generate-reactflow build/design.yaml -o web/public/graph.reactflow.json
vg export-excel build/design.yaml -o build/design.xlsx
```

也可以提供一键命令：

```bash
vg build --rtl examples/rtl --diagram examples/algo/algo.svg --signals examples/algo/fixed_signals.xlsx --mapping examples/algo/block_mapping.xlsx --top top
```

## 11. 校验器设计

### 11.1 Schema 校验

校验字段类型、必填字段、枚举值和基本格式。

### 11.2 引用校验

1. instance 引用的 module 必须存在。
2. connection 引用的 instance 必须存在。
3. connection 引用的 port 必须属于该 instance 对应的 module。
4. connection 引用的 net 必须存在。
5. block mapping 引用的 module 必须存在。
6. 框图 signal 必须能匹配到定点信号表。

### 11.3 语义校验

1. `s(width,frac_width)` / `u(width,frac_width)` 格式必须合法。
2. `width > 0`。
3. `0 <= frac_width <= width`。
4. port 与 net 位宽必须一致，除非显式声明转换。
5. output/inout 驱动同一 net 时需要检查多驱动。
6. required input 不允许悬空。
7. bus slice 不能越界。
8. 参数覆盖名称必须存在。

校验输出分为：

```text
ERROR   阻止生成
WARNING 允许生成但提示风险
INFO    信息提示
```

## 14. 待用户确认点

进入实现前仍需确认：

1. block 到 Verilog module 的映射关系使用 Excel 表，还是单独 YAML 配置文件。
2. 多层级输出第一阶段是生成单个 top `.v` 展开结构，还是按层级生成多个 `.v` 文件。
3. 端口匹配规则是依赖端口同名，还是需要端口映射表。
4. 位宽不匹配时第一阶段是报错，还是允许自动截断/扩展。
5. 是否需要在生成代码中显式输出所有默认参数。
