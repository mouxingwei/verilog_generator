# Verilog 模块结构与连线管理工具原始需求文档

日期：2026-05-13

## 1. 背景

当前 Verilog/SystemVerilog 项目中的模块结构、实例化关系、端口连线、参数配置通常分散在 RTL 文件、Excel 表格、算法框图、手绘框图和工程师经验中。随着模块数量增加，人工维护顶层连线容易出现漏连、错连、位宽不匹配、多驱动、悬空端口等问题。

本项目希望建立一种适合 AI 与人类共同维护的模块结构管理方式：AI 看到的是结构化数据，人类看到的是表格和图形界面，最终可以稳定生成 Verilog 结构代码。

## 2. 核心目标

1. 建立 Verilog 模块、端口、实例、网络、连接、参数的结构化描述方式。
2. 支持 AI 读取、分析、修改模块结构与连线关系。
3. 支持人类通过 Excel 批量导入、导出和审查数据。
4. 支持人类通过图形界面查看模块拓扑和编辑连线。
5. 支持从结构化数据生成顶层 Verilog `.v` 例化代码。
6. 支持从已有 Verilog/SystemVerilog 代码中提取模块例化所需的端口、参数、位宽等接口信息。
7. 支持将算法定点化框图和信号属性表格作为原始输入，其中框图提供连接关系，表格提供信号位宽和定点属性。
8. 支持自动校验连接合法性，降低人工维护错误。

## 3. 已确认输入来源

当前已确认需要支持以下原始输入来源：

| 输入来源 | 已确认用途 |
| --- | --- |
| Excel 表格 | 人类批量维护模块、端口、实例、连接、参数、信号位宽等信息 |
| 已有 Verilog/SystemVerilog 代码 | 提取模块例化所需的端口、参数、位宽等接口信息 |
| 算法定点化框图 | 提供算法 block、算子节点、数据流和连接关系 |
| 算法定点化信号表格 | 提供信号位宽、是否有符号、整数位、小数位、舍入和饱和等定点属性 |
| 图形界面 | 提供模块拓扑查看和连线编辑能力 |
| AI 修改请求 | 基于结构化数据进行局部修改、检查和生成建议 |

## 4. 已确认第一阶段约束

1. 第一阶段优先链路为“已有 Verilog 接口提取 + 算法框图 + 表格导入”，不是单独以 Excel 手工维护连线为主。
2. 算法框图当前来源为“亿图”，第一阶段导入格式支持 `.eddx` 或 SVG，具体优先级以后续样例文件验证为准。
3. 工具需要支持多个层级的工程结构，不只服务单个顶层模块。
4. 框图连线已有稳定信号名，工具应直接使用框图中的信号名进行连接和表格匹配。
5. 框图中的 block 需要映射到固定 Verilog 模块库。
6. 信号位宽和定点属性表当前没有现成 Excel 模板，需要在需求阶段定义模板字段。
7. 定点表字段第一阶段至少包括信号名和信号定点位宽，定点格式参考 `s(11,1)`、`u(11,5)`。
8. Verilog 接口提取第一阶段语法范围以 Verilog-2005 为目标。
9. 第一阶段图形能力以“生成可查看拓扑图”为目标，暂不要求图形化编辑。
10. 第一阶段生成目标为 Verilog `.v` 文件。

## 5. 典型用户

| 用户角色 | 关注点 |
| --- | --- |
| RTL 工程师 | 端口定义、实例连接、参数配置、生成代码可读性 |
| 架构设计人员 | 模块层级、数据通路、控制通路、接口关系 |
| 算法工程师 | 算法框图、定点化位宽、符号位、小数位、舍入和饱和策略 |
| 验证工程师 | 信号完整性、悬空端口、多驱动、位宽一致性 |
| AI 助手 | 结构化输入、局部修改、可校验输出 |

## 6. 功能需求

### 6.1 模块结构管理

- 维护模块定义，包括模块名、描述、分类、来源文件。
- 维护端口定义，包括端口名、方向、位宽、类型、时钟域、复位域、说明。
- 维护模块实例，包括实例名、模块类型、层级路径、参数覆盖。
- 维护内部 net/wire/logic，包括名称、位宽、类型、说明。
- 维护实例端口到 net 的连接关系。

### 6.2 已有 Verilog 接口提取

- 支持扫描已有 Verilog/SystemVerilog 源文件，提取 module 定义。
- 第一阶段接口提取以 Verilog-2005 语法为目标。
- 支持提取模块参数，包括参数名、默认值、表达式文本和可选说明。
- 支持提取模块端口，包括端口名、方向、位宽表达式、数据类型和声明来源。
- 支持将提取结果写入结构化 IR，供用户在 Excel 或图形界面中选择模块并创建实例。
- 支持对无法解析或包含复杂宏、generate、接口类型的模块给出告警，而不是静默生成错误数据。
- 初期重点提取“例化需要的信息”，不要求完整理解 RTL 行为逻辑。

### 6.3 算法定点化输入

- 支持将算法定点化框图作为原始输入，提取算法模块、算子节点、数据流边和连接关系。
- 算法框图当前来源为亿图，第一阶段支持 `.eddx` 或 SVG 导入，具体优先级以后续样例文件验证为准。
- 框图连线已有稳定信号名，工具应保留并使用这些信号名。
- 框图中的 block 需要映射到固定 Verilog 模块库。
- 支持将表格作为信号属性输入，维护信号名和信号定点位宽。
- 信号定点位宽采用紧凑格式表达，参考 `s(11,1)`、`u(11,5)`，其中 `s` 表示 signed，`u` 表示 unsigned。
- 信号属性表当前没有现成模板，工具需要定义 Excel 模板字段。
- 支持将框图连接关系与表格信号属性合并为统一 IR。
- 支持检查框图中的信号是否都能在表格中找到对应属性，表格中的信号是否都被框图引用。
- 支持将算法级 block 映射到后续 Verilog 模块实例或算子模板。
- 初期围绕亿图输入和定点表格输入展开，不在需求未确认前扩展到其他框图来源。

### 6.4 Excel 导入导出

- 支持将结构化数据导出为 Excel 工作簿。
- 支持从 Excel 工作簿导入模块、端口、实例、连接、参数等表。
- 支持工程师批量修改连接表后重新导入。
- 导入时需要进行字段校验、引用校验和语义校验。

### 6.5 AI 协同

- AI 应修改结构化 IR，而不是直接修改生成后的 Verilog。
- AI 输出应受到 JSON Schema 或等价约束限制。
- 支持局部上下文输入，例如只给 AI 当前模块的实例和连接片段。
- 支持修改后自动校验并生成差异报告。

### 6.6 可视化查看

- 支持以模块实例为节点、信号连接为边显示拓扑。
- 支持端口级连接显示。
- 支持拖拽节点位置。
- 支持高亮悬空端口、位宽不匹配、多驱动等问题。
- 支持图形布局信息与结构数据分离，避免 UI 坐标污染核心设计数据。
- 第一阶段只要求生成可查看拓扑图，不要求在图形界面中创建、删除或修改连接。

### 6.7 Verilog 生成

- 从结构化 IR 生成顶层或子系统 Verilog `.v` 文件。
- 支持模块例化、参数覆盖、端口映射、wire/logic 声明、assign 生成。
- 支持生成前校验，校验失败时拒绝输出或标记风险。
- 生成文件应尽量稳定，便于 Git diff。

## 7. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 可维护性 | 数据模型清晰，便于脚本、AI 和人类共同理解 |
| 可扩展性 | 支持从单文件扩展到多模块、多层级、多文件 |
| 可追踪性 | 结构化文件适合 Git diff 和代码审查 |
| 可恢复性 | Excel、IR、图形布局、算法框图之间可以重新生成或修复 |
| 可校验性 | 支持 schema 校验和硬件语义校验 |
| 易用性 | 工程师可以继续使用 Excel 批量编辑，算法工程师可以沿用框图加表格的定点化输入方式 |

## 8. 初始范围

第一阶段优先实现：

1. 从已有 Verilog-2005 代码提取模块端口、参数、位宽等接口信息。
2. 支持亿图 `.eddx` 或 SVG 算法框图和新定义的信号属性表格导入，形成算法级连接和定点位宽 IR。
3. Excel 与结构化 IR 双向转换，其中第一阶段重点是信号属性表模板和导入导出。
4. IR schema 定义。
5. 基础语义校验。
6. 支持多层级结构管理和 Verilog `.v` 结构代码生成。
7. IR 到 Mermaid 或 Graphviz 拓扑图生成，用于查看，不要求编辑。

第一阶段暂不强制实现完整 Web 图形编辑器，但数据模型需要为后续图形化编辑器预留字段和接口。

## 9. 暂不纳入范围

- 完整 RTL 行为逻辑生成。
- 完整 EDA 替代工具。
- 复杂综合、时序、形式验证流程。
- 完整 IP-XACT 兼容。
- 多人实时协同编辑。
- 完整算法自动优化和自动定点化决策。
- 第一阶段图形化编辑连接关系。
- 第一阶段生成 SystemVerilog `.sv`。

## 10. 待确认问题

以下问题需要用户确认后，才能继续细化技术选型和开发方案。

### 10.1 使用场景范围

1. 目标用户是个人使用为主，还是多人协作使用？
2. 多层级工程中，层级边界是由亿图框图表达、由 Excel 表达、由 Verilog 已有模块层级表达，还是三者都可能表达？

### 10.2 算法定点化输入

1. `.eddx` 和 SVG 两种格式中，是否可以提供一个实际样例用于确认可解析信息量？
2. 框图中的 block 与固定 Verilog 模块库之间的映射关系由哪里维护：框图 block 名称、Excel 映射表，还是单独配置文件？
3. 定点格式 `s(11,1)`、`u(11,5)` 中两个数字的准确语义是什么？例如总位宽和小数位，还是整数位和小数位？
4. 定点表是否还需要说明字段，例如备注、来源、量化策略或仿真误差？

### 10.3 Verilog 接口提取

1. Verilog-2005 范围内是否需要支持宏定义、include、parameter 表达式和 generate？
2. 提取结果只用于新建实例，还是也需要反向检查已有顶层例化是否正确？
3. 如果解析失败，是允许人工补全接口信息，还是必须阻止后续流程？

### 10.4 Excel 导入导出

1. Excel 是作为主要人工编辑入口，还是只作为导入导出交换格式？
2. 连线表更偏好“起点/终点按行记录”，还是“连接矩阵”？
3. 是否需要支持一个 Excel 文件里同时管理多个设计或多个 top？

### 10.5 可视化查看

1. 查看拓扑图需要到端口级连线，还是只需要模块级/block 级连接？
2. 是否需要支持人工布局保存，例如节点坐标、分组、颜色、层级折叠？
3. 是否需要在图上展示位宽和定点属性？

### 10.6 生成输出

1. 生成内容只包括结构例化和连线，还是也需要生成算子模块模板、wrapper、testbench 或文档？
2. 生成代码的命名规则、缩进风格、端口排序是否需要匹配已有项目规范？
3. 生成前遇到 warning 时，是允许继续生成，还是必须人工确认？

### 10.7 校验规则

1. 第一阶段必须实现哪些校验：位宽、方向、多驱动、悬空端口、时钟复位域、定点格式一致性？
2. 位宽不匹配时是否允许自动插入截断、扩展、符号扩展或舍入饱和逻辑？
3. 定点格式转换是只做检查，还是需要自动生成转换模块或 assign 逻辑？
4. 是否需要生成校验报告供人工审查？

## 11. 验收标准

1. 可以从已有 Verilog-2005 模块文件提取端口、参数和位宽信息，并写入 IR。
2. 可以从亿图 `.eddx` 或 SVG 算法定点化框图提取多层级连接关系。
3. 可以将框图 block 映射到固定 Verilog 模块库。
4. 可以使用新定义的 Excel 模板维护信号属性表，至少包含信号名和 `s(11,1)`/`u(11,5)` 风格的定点位宽。
5. 可以导入 Excel 并生成合法的结构化 IR。
6. 可以对 IR 进行 schema 和基础语义校验。
7. 可以从 IR 生成可读的 Verilog `.v` 顶层文件。
8. 可以从 IR 生成可查看的拓扑图。
9. AI 可以基于 IR 修改连接关系，并通过校验器发现明显错误。
